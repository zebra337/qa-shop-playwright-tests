# QA-Shop E2E-тесты (Playwright)

Набор Playwright-тестов для учебного интернет-магазина **Лавка** (см. [zebra337/qa-shop](https://github.com/zebra337/qa-shop)).
Тесты проверяют основные сценарии: каталог и поиск, корзину, промокоды, оформление заказа, регистрацию и вход.

## Запуск

Требуется Node.js 18+.

~~~bash
npm install
npx playwright install --with-deps chromium   # одноразово: установка браузера
npm test                                     # прогон; URL берётся из BASE_URL
~~~

По умолчанию тесты идут против публичного стенда: `https://qa-shop-6xeq.onrender.com`.
Адрес переопределяется переменной окружения (например, для локального пода):

~~~bash
BASE_URL=http://localhost:3000 npm test
~~~

Полезные команды:

- `npm run test:headed` — прогон с открытым браузером;
- `npm run test:ui` — интерактивный Playwright UI Runner;
- `npm run report` — показать HTML-отчёт;
- `npx playwright test cart.spec.ts` — запустить один файл тестов.

> Стенд развернут на Render Free и засыпает без трафика: первый запрос после паузы
> может занимать до 60 секунд. В конфиге учтён увеличенный таймаут (120 c на тест).

## Структура

| Файл | Что проверяет |
|-------------------------|---------------|
| `tests/catalog.spec.ts` | витрина (16 товаров), фильтр по категории, поиск по названию и описанию, сортировки, наличие, карточка товара, 404 |
| `tests/cart.spec.ts` | добавление из витрины и с карточки, счётчик, кнопки ±, ввод количества, удаление, очистка, лимит остатка, пустая корзина |
| `tests/promo.spec.ts` | SALE10 (−10 %), WELCOME500 (−500 ₽ от 2000 ₽ и отказ ниже порога), неизвестный код, сброс, пересчёт скидки |
| `tests/checkout.spec.ts` | гостевой заказ (самовывоз и курьер, наличные и карта), доставка 300 ₽, бесплатно от 3000 ₽, валидация полей, заказы пользователя |
| `tests/auth.spec.ts` | регистрация, валидация полей, занятый e-mail, неверный пароль, сессия после перезагрузки, выход, гостевая защита страниц |
| `tests/utils.ts` | помощники: уникальные e-mail, добавление товара, чекаут, регистрация, проверка сумм в ru-локали |

## Найденные баги

Пометка «стенд» — подтверждено запросами к живому серверу, «код» — найдено по исходникам.

1. **Открытый доступ к `/metrics`** — *стенд, средняя.* Prometheus-метрики отдаются любому
   без аутентификации и содержат бизнес-цифры: число зарегистрированных пользователей,
   количество заказов и их выручку. Стоит закрыть метрики секретным заголовком или IP-фильтром.
2. **Корзина, сессии и вход живут в памяти процесса** — *стенд, средняя.* Перезапуск контейнера
   (на Render Free — после засыпания или деплоя) сбрасывает корзины, сессии и заказы гостевых сессий.
3. **500 вместо 404 при изменении количества удалённого товара** — *код, низкая.*
   `PATCH /api/cart/items/:productId` с `qty > 0` для товара, отсутствующего в каталоге,
   падает с `TypeError` (`.stock` у `undefined`) и отдаёт 500.
4. **Кнопка «+» не ограничена наличием** — *код, низкая.* У поля количества на карточке товара
   задан атрибут `max`, но кнопка «+» его не проверяет: пользователь получает отказ сервера
   вместо мягкого ограничения на клиенте.
5. **Промокод молча исчезает** — *код, низкая.* Если после применения `WELCOME500` сумма товаров
   опускается ниже порога (например, после удаления позиции), скидка пропадает из сводки
   без уведомления, хотя код остаётся в сессии.
6. **Вход перезаписывает владельца сессии вместе с корзиной** — *код, низкая.*
   Регистрация/вход меняют `userId` уже активной сессии, а корзина в сессии остаётся:
   корзина гостя может «переехать» в чужой аккаунт.
